# Hybrid experiment design

## Data and ownership

Keep this ruleset in a small opt-in `pacman/hybrid/` subsystem. Reuse `grid`, `mapgen`, `rng`, and `stats`, but not the legacy environment, evaluator, features, or policy loader. The latter encode corner goals, an omniscient ghost, and solver-filtered evaluation. A core migration would remove duplication, but changes the semantics of existing commands, artifacts, and tests. Isolation preserves those historical results while allowing a single authoritative implementation of the new rules. Do not fork map generation or BFS.

Use immutable values at agent boundaries:

- `PacObservation(pacman, ghost, pellets, known, turns_left)` contains the two remaining pellet positions as a frozenset, 25 remembered UNKNOWN/OPEN/WALL cells, and no true wall map. Sense neighboring walls on reset and after Pac-Man moves. Pac-Man may use known-open cells for planning and unknown cells as exploration frontiers.
- `GhostObservation(cell, visible_pacman: Cell | None, memory, turns_left)` contains only the current visible position when true-map row/column LOS is clear. `memory` holds last seen cell, optional direction, age, search target and remaining search budget. Its direction is inferred only from two consecutive visible observations with a single-cell displacement; lost sight, an ambiguous displacement, or a stationary observation clears it. It never contains current hidden Pac-Man coordinates. The ghost may know the static map for BFS, but its policy and reward get no hidden Pac-Man state.
- `EpisodeState` privately owns true positions, walls, remaining pellets, ghost memory, and turn count. Policies cannot inspect it. `Outcome` is win, loss, or tie. A single `finish(outcome)` closes pending transitions exactly once for either actor, including termination before the ghost acts and the 100th-turn timeout.
- A frozen policy is a read-only copied table plus immutable metadata. The trainer owns mutable tables. Evaluation accepts only frozen policies, with content hashes checked before and after a run.

On reset choose two distinct open cells without replacement using the pellet stream, excluding both fixed spawn cells. Each turn follows existing `env.py` order: Pac-Man moves, collision loses, collect a pellet once, second pellet wins, otherwise update sensing and ghost visibility, then ghost moves and collision loses. After turn 100, a nonterminal game ties. Invalid wall moves remain in place. A terminal transition receives no bootstrap; timeout is a tie, never a capture or success.

## Hybrid ghost and learning

At each ghost turn, visibility is measured from its current cell after Pac-Man has moved. Visible Pac-Man refreshes memory and directs BFS toward the observed location. Without visibility, BFS first reaches the last seen location. Once there, select a bounded search destination from deterministic candidate cells around that location, for example reachable neighbors and a forward candidate when observed direction exists. Filter duplicates and unreachable choices. Baseline selects uniformly from the same candidate set; learned ghost selects epsilon-greedy Q values. Replan via BFS each turn, reacquire immediately on LOS, and decrement a fixed memory/search budget each hidden turn even if blocked or already at a destination. On expiry, clear all memory and choose random legal moves until reacquisition. Use a stable candidate ordering. Thus both opponents share visibility, pursuit, pathfinding, movement probability, and expiration; only the search choice differs. Store all constants in versioned rules, not tuned after test results.

A search choice is a semi-Markov action. Hold `(state, choice, elapsed, discounted_reward)` until the next search choice or episode end. Accumulate only legitimate observations and real outcome rewards. Update with `R + gamma**elapsed * max(Q(next_state))` at the next choice, or `R` on termination. Capture receives a positive ghost reward whether it occurs in pursuit, search, or on Pac-Man's move before ghost action. If no search decision is pending, there is no Q update. Tie and Pac-Man win get distinct non-success terminal rewards. No distance shaping based on a hidden current position. A transition interrupted by reacquisition or expiry remains pending until another choice or terminal event, with elapsed time continuing; this makes credit assignment explicit and avoids falsely rewarding timeouts.

Pac-Man uses a compact tabular Q state over current legal/open-neighbor mask, ghost relative direction and distance buckets, remaining pellet count, first planned step to a pellet or exploration frontier, and turns-left bucket. Avoid raw map or pellet coordinates in the index: the existing 122,880-row learner is already sparse, and including full memory would explode coverage. Mask illegal moves and use deterministic tie-breaking. Reward collection once and terminal win/loss, with a modest step cost; use terminal timeout targets. Ghost state similarly buckets last observed direction, local junction geometry, memory age/budget and relative search candidate. Record visit counts and zero-visit action rates to expose sparsity. The lossy representation is partially observable, not a claim of a Markov state. First measure whether it learns; expand features only from validation evidence.

## Training and interfaces

Expose `python -m pacman.hybrid train`, `evaluate`, and `watch`. `train` takes an output directory, replicate seed, episode budgets and fixed rules/config. Train Pac-Man against the baseline first and retain checkpoints; freeze a named checkpoint pool, then train the ghost against that pool; freeze the ghost and train Pac-Man against a declared mixture of baseline and frozen ghost. Sample the pool with its own RNG. No table is updated while acting as an opponent. Independent replicate seeds change both initialization and episode stream, not merely the order of identical games. Derive separate labeled streams from replicate/episode keys for layout, pellet, ghost movement/search, Pac-Man exploration, and opponent sampling; evaluate matched scenarios across policies. Map split membership must still be checked via the existing map generator's layout partition rules.

Validation selects checkpoints and any feature/hyperparameter changes; test remains untouched until selection is fixed. If feasible run five independent training seeds and report the full Pac-Man-by-ghost cross-play matrix, per-seed win rates and range. `evaluate` runs every scheduled map/game, including unwinnable instances, and reports wins, losses, ties, denominator, 95% Wilson interval and seed list. The target is observed wins/games >= 55% against the frozen learned ghost, not a filtered rate. State separately whether the interval includes 55%; do not claim success if the measured target fails. Include baseline comparison under identical rules and seeds. `watch` loads matching frozen artifacts and renders the actual pellets and observations, with the same episode loop as training and evaluation.

Write new policy archives with distinct `format_version`, `rules_version`, `feature_version`, actor type, table shape/dtype, full rules and training config, seed derivation version, checkpoint provenance and opponent hashes. Reject unknown versions, malformed or nonfinite tables, incompatible rules or actor types, and v1 legacy archives. Write atomically to a new run directory. Save per-game records with map, pellet and stochastic seed keys, policy hashes, outcomes and steps so a result can be replayed. Preserve all legacy reports and files.

## Verification gates

Test identical ghost observations and decision rewards for states differing only in hidden Pac-Man location; test LOS loss, reacquisition, and direction only from consecutive visible observations. Exercise deterministic BFS pursuit, bounded search expiry, and baseline/learned parity outside search choice. Test exactly two unique legal pellets, collection once, simultaneous collision precedence, second-pellet win before ghost action, and turn-100 tie. Exercise capture before ghost action and during variable-duration search, one terminal Q update, discounted elapsed bootstrap, and no timeout capture reward. Verify frozen opponent tables by hashes, deterministic replay and separated streams, rejection of legacy/incompatible artifacts, and unchanged legacy tests. Run train, evaluate and watch with small budgets as integration checks before the full registered training run. Report the actual aggregate and cross-play outcomes even if the 55% target is missed.
